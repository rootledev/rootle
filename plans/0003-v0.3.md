# 0003 — v0.3: Interaction layer (yank · keybinds · command line · settings)

The app-wide interaction furniture, mock-UI-first per flow — each flow
is its own review checkpoint before any backend wiring. Ordered by
dependency and review cost.

## 1. Yank (`␣ y`) — copy remote URL to clipboard

- Works in **BROWSE** (browser panes) and in the **global search view**.
- What gets yanked, by context:
  - browser, repo level → repo URL (`https://github.com/owner/repo`)
  - browser, dir/file → blob/tree URL
    (`…/blob/<branch>/<path>`, `…/tree/<branch>/<path>`)
  - search view, hit → file URL; grep hit → file URL **with line
    fragment** (`#L42`, range `#L42-L45` when the region spans lines)
- Feedback: transient toast in the modeline ("yanked …"), never a
  dialog (plans/0001 §5).
- Clipboard: OSC 52 escape first (works over SSH/tmux), fall back to
  shelling out (`wl-copy`/`xclip`/`pbcopy`). No new heavy deps.
- Keymap: leader table gains `y` (hint derives, as always).

## 2. Keybinds popup (`?`)

- `?` in BROWSE opens a centered popup listing every keybinding,
  **derived from `src/keymap.rs`** — never a hand-written list; the
  table is the single source of truth for dispatch *and* help.
- Scrolls with `j/k` (+ `h/l` reserved if columns appear), grouped by
  mode with section headers. Esc closes. One popup deep as usual.
- Needs the keymap table to carry per-mode entries with descriptions —
  mostly exists; popup renders `hints()` plus the full dispatch tables.

## 3. Command line (`:`)

- `:` opens a **transient command input anchored above the modeline**
  (vim/helix style): a one-line strip, not a centered popup.
- As you type, a small option list pops above the input, filtered
  incrementally (commands: `settings`, `clone`, later `theme`, …).
  Enter runs the selected/typed command, Esc cancels.
- Reuses `VimInput` in transient mode — same feel as `/` filters.
- Command registry is a data table (name → description → Action), so
  the option list is derived, mirroring the keymap table pattern.

## 4. Settings popup (`:settings`)

- Centered popup with **tabs across the top**, one per config section
  (`[editor]`, `[theme]`, `[cache]`); Tab / `h`/`l` switch tabs, `j/k`
  move between fields, values edit in place via `VimInput`.
- Writes to `~/.config/ghx/config.toml` and **hot-reloads**: theme
  changes repaint live (Theme is rebuilt and handed down), editor/
  cache settings take effect on next use. No restart.
- State: a `SettingsPopup` component rendering from the parsed
  `Config` schema — fields derived from the serde structs so a new
  config key shows up without UI code (mock checkpoint decides how far
  the derivation goes vs hand-laid fields).

## 5. Milestones (each = mock UI checkpoint, then wiring)

**Mock checkpoint done for all four flows** (trigger points + screens,
no backend): `?` keybinds popup (derived from the keymap tables,
j/k scroll), `:` command line (strip above the modeline, filtered
options, arrows pick), `:settings` popup (tabs per config section,
in-place field editing), `␣ y` trigger reserved in the leader table
(yank URLs land in the wiring pass). Frame tests in `tests/render.rs`,
scenarios in `e2e/test_interaction.py`.

1. Yank wiring — OSC 52/clipboard + URL formatting rules.
2. Keybinds wiring — none needed (pure derivation already).
3. Command line → real command effects.
4. Settings write-back + hot reload (Theme rebuild handed down).

## 6. Test/verification contract

Same as v0.2: unit tests per component, `tests/render.rs` frames for
each popup (open/close without residue), e2e scenario per flow
(`e2e/test_interaction.py`), clipboard asserted via a `GHX_CLIPBOARD`
file override in the harness (no real clipboard in CI).
