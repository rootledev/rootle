# 0004 — v0.4: Clone flow (VISUAL mode · `:clone` wizard)

Multi-select + a guided clone wizard. Mock-UI-first; the wizard
screens are reviewed before any git/ssh wiring.

## 1. VISUAL mode (multi-select)

- `v` in BROWSE enters VISUAL: rows toggle selection with `<Space>`,
  `j/k` move, `v`/Esc exits. Selected rows get a checkbox affordance
  (`[x]`/`[ ]`) alongside the existing selection styling.
- Selectable units: repos at the repo level, files/dirs inside a repo
  tree. The mode chip exists already (`[VISUAL]`, pink — plans/0001 §2).

## 2. `:clone` wizard

Entered via the command line (plans/0003 §3). Takes the VISUAL
selection and walks it upward: **files/dirs resolve to their nearest
containing repo** (tree traversal up), so the wizard clones repos,
never subtrees (v0.4; sparse/subtree clone is a later phase).

Three screens, one wizard component with a screen stack:

```
screen 1: repos          screen 2: destination        screen 3: summary
┌──────────────────┐     ┌──────────────────┐         ┌──────────────────┐
│ [x] ratatui      │     │ ~/workspace/     │         │ clone 3 repos    │
│ [x] comfy-table  │     │  ▸ rust/         │         │ → ~/workspace/rs │
│ [ ] templates    │     │  ▸ go/           │         │                  │
│                  │     │                  │         │ [back] [clone!]  │
│ [next]           │     │ [back] [next]    │         │                  │
└──────────────────┘     └──────────────────┘         └──────────────────┘
```

1. **Repos** — checkbox list of the resolved repos; toggle with
   `<Space>`, `j/k` move; `next` (Enter on the button / `w`?) proceeds.
2. **Destination** — a mini miller browser over the **local**
   filesystem, rooted at rootle's launch cwd: `h/l` out/in, `j/k` move,
   arrows also work. Dirs only; Enter/`l` descends; `next` accepts the
   shown path.
3. **Summary** — what will happen: N repos, the destination tree
   (`dest/└ org/…`), and the exact command lines. Clones land in
   `<dest>/<org>/<repo>` — same-named repos across orgs never
   collide. Buttons centered at the bottom. `back` returns a screen; **Esc at
   any point closes the entire wizard** (no partial state).

- Buttons are keyboard-driven focus targets (Tab/`h`/`l` between list
  and buttons), consistent with the search view's field row.
- Wiring (post-mock): `git clone https://github.com/owner/repo` into
  `<dest>/<repo>`, jobs on worker threads with progress in the
  modeline; failures land in the summary screen, never block the UI.

## 3. Mock checkpoint status

**Mock done**: `v` enters VISUAL (checkboxes on every pane, marks
survive cascades, pink chip), `:clone` opens the wizard — screen 1
repo checkboxes (marks resolve to repos, files fold up to the open
repo), screen 2 local-dir mini browser rooted at the launch cwd
(`h/l/j/k` + arrows, dotdirs hidden), screen 3 summary with the clone
command lines, `back`/`next` buttons keyboard-driven, Esc cancels the
whole wizard from any screen. No git runs yet.

## 4. Open questions for the mock review

- Screen-to-screen key: Enter on `[next]` vs a dedicated `w`/Tab
  cycle — mock will pick one, review decides.
- Destination screen: allow typing a new folder name (inline input) or
  stay browse-only for v0.4?
- Clone depth flag (`--depth 1` default?) and protocol (https vs ssh)
  — probably a settings key (plans/0003 §4) rather than wizard chrome.
- Resolved in review: `dest/<org>/<repo>` targets; marks persist after
  VISUAL (drive `:clone` + `␣ d`); org marks expand down; `:` opens
  from VISUAL.
